# TAUGHT TUT

*Learn the Angles. Feel the Beat.* — 웹캠으로 텃팅 자세를 배우는 웹서비스 (King Tutting 계열, 팔 중심)

## 실행

```bash
npm install
npm run dev        # http://localhost:5173  (디버그 패널: /?debug=1)
npm test           # 각도 계산·포즈 판정 단위 테스트
npm run build      # 타입 검사 + 빌드
```

카메라는 HTTPS 또는 localhost에서만 동작합니다. 영상과 관절 데이터는 브라우저 안에서만 처리되며 서버로 전송되지 않습니다.

## 현재 구현 범위

- 사용자가 버튼을 누른 뒤에만 카메라 권한 요청 (거부·장치 없음·사용 중·연결 끊김 안내)
- MediaPipe Pose Landmarker(Lite)로 어깨·팔꿈치·손목 추적, 거울 화면 표시
- 레슨 3개 (아래 표), 포즈 데이터 기반 판정 (양팔 지원)
- Perfect / Good / Adjust 피드백과 교정 안내, 목표 자세 미리보기, 디버그 모드
- 네오펑크 테마
- **리듬 챌린지 FIRST TUT FLOW** (상단 PERFORM 탭): 직접 합성한 100BPM 비트, 8카운트 × 4회, 동작별 평가, 점수·콤보, 결과 화면, 최고 점수 저장
- **FREESTYLE** (상단 FREESTYLE 탭): 정해진 자세 없이, 텃팅의 원칙(직각, 딱 멈추기, 곧은 이동)으로 채점

아직 없음: 영상 녹화·SNS 공유·결과 카드, 학습 진도 저장.

## 리듬 챌린지 — FIRST TUT FLOW (PERFORM 탭)

> ⚠️ **안무와 평가 기준은 모두 "기획 초안 + 임시 기준"입니다.**
> 실제 사람이 춘 기준 안무(MediaPipe 좌표)로 검증하기 전이며, 아래 숫자는 규칙 기반으로 정한 가정값입니다.
> 사람이 실제로 수행 가능한 움직임인지도 **확인 필요**입니다. 시범 그림은 보여주기용이고 채점에는 쓰이지 않습니다.

100BPM(한 카운트 0.6초), 4/4, 8카운트 × 4회 = 안무 19.2초, 카운트다운 4박 + 엔딩 2박 포함 약 23초.
음악은 Web Audio로 직접 합성한 오리지널 비트라 저작권 문제가 없습니다.

| 카운트 | 동작 | 평가하는 것 | 측정하지 못하는 것 (점수 미반영) |
|---|---|---|---|
| 1~2 | Open & Slide (열고 밀기) | 양 손목의 이동 방향·거리·곧음, 끝난 박자 | 손목 회전, 손가락·손바닥 |
| 3 | Box (박스) | 양팔 팔꿈치 각도·팔 방향·좌우 균형 | 손목 꺾임, 손가락 |
| 4 | Rotate (회전) | 윗팔·아랫팔 방향이 바뀐 정도(시작·끝·회전량·방향) | 앞뒤로 도는 회전, 손목 이동 경로 |
| 5~6 | Arm Wave (암 웨이브) | 손목·팔꿈치·어깨가 움직인 **순서**(대략), 움직인 관절 수 | 손목 굴림, 손가락, 관절의 세밀한 곡선 |
| 7 | Fold (접기) | 양 팔꿈치 각도가 줄어든 정도 | 팔이 가려질 때의 정확한 각도 |
| 8 | Final Hit (마지막 포즈) | 최종 자세 + 박자 | 손목 꺾임, 손가락 |

- 판정: 완성도(0~100)와 박자 오차(ms)를 **따로** 보고 합칩니다.
  Perfect = 완성도 85↑ & 박자 ±150ms 이내, Good = 완성도 70↑ & ±250ms 이내, 그 외 Miss
  (동작형은 시작·끝이 흐려서 박자 범위를 1.5~2배로 넉넉하게). 값은 `src/data/challenge.ts`의 `RHYTHM_JUDGE`.
- 자세형(Box, Final Hit)은 학습 모드와 같은 상한 규칙: 한 항목이라도 허용 범위를 벗어나면 Perfect 완성도 불가,
  크게 틀리면 Good 완성도 불가 (평균 점수로 가려지지 않게).
- 점수: Perfect 100 / Good 60 / Miss 0, 콤보 보너스 = 점수 × (1 + 0.1 × min(이전 콤보, 10)). 만점 4,250.
- **화면 연출(하이웨이):** 웹캠 영상에 보라·핑크 색감과 비네팅을 입히고, 원근 레인 위로 동작이 **타일**이 되어 판정선으로 다가옵니다.
  길게 이어지는 동작(Slide, Rotate, Wave, Fold)은 롱노트처럼 긴 타일이고 뒤쪽 끝이 판정선에 닿는 순간이 동작 완료 박자,
  자세(Box, Final Hit)는 짧은 타일이고 가운데가 닿는 순간이 목표 박자입니다. 판정이 나오면 판정선에서 링과 파티클이 터집니다.
  성공 색은 형광 초록 대신 아이스(`--color-neon-ice`)를 씁니다. (`HighwayCanvas.tsx`, `utils/highway.ts`)
- 좌표는 몸 크기 기준(원점=어깨 중점, 단위=어깨 너비)으로 정규화해서 체형·카메라 거리 차이를 줄입니다.
- 카메라 지연 보정 슬라이더(기본 100ms는 **가정값**)로 박자 어긋남을 조정할 수 있습니다.
- 카메라가 끊기면 챌린지를 중단합니다 (일시정지 기능은 아직 없음).

### 기술적 제약

- 한 카운트가 0.6초라 빠른 동작은 모션 블러로 추적이 흔들릴 수 있습니다 (BPM은 `FIRST_TUT_FLOW.bpm`으로 조정).
- 카메라 정면 2D만 보므로 앞뒤 방향 회전은 부정확합니다. 팔이 몸에 가려지는 동작(Slide 시작의 팔 교차, Fold)은 인식이 끊길 수 있습니다.
- Pose Landmarker는 손목 굴림·손가락·손바닥 방향을 측정하지 못합니다. 웨이브는 "관절이 순서대로 움직였는가"만 대략 봅니다.
- 인식 지연은 기기마다 다릅니다 (**확인 필요**).

### 기준 안무 만들기 (다음 작업)

진짜 기준은 실제 사람이 춘 동작에서 나와야 합니다. `?debug=1` 로 챌린지를 한 판 한 뒤 결과 화면의
**"기준 데이터 저장 (JSON)"** 으로 프레임별 좌표를 내려받을 수 있습니다 (영상은 포함되지 않고 좌표만).
텃팅 경험자가 같은 비트에 맞춰 여러 번 녹화한 데이터로 동작별 기준값(이동 거리, 각도, 순서, 박자 오차)을 교정하는 것이 목표입니다.

> 테스트의 가상 연기자는 시범 키프레임을 보간한 입력이라 **로직의 자기 일관성만** 확인합니다. 실제 사람 검증이 아닙니다.

## FREESTYLE — 자세는 자유, 원칙으로 채점 (FREESTYLE 탭)

텃팅은 정해진 몇 가지 자세로 딱딱 나뉘지 않으므로, 템플릿과 비교하지 않고 **움직이다가 박자에 맞춰 딱 멈추는 순간(히트)** 을 찾아 평가합니다.

> ⚠️ **모든 기준값은 임시입니다** (`src/data/freestyle.ts`). 실제 사람 데이터로 조율한 적이 없습니다.

| 원칙 | 측정 | 비중 |
|---|---|---|
| 직각·직선 | 멈춘 순간 윗팔·아랫팔이 수평/수직에 가까운 정도 (어떤 모양이든 상관없음, ±20° 이내 만점) | 55% |
| 딱 멈추기 | 속도가 정점의 절반 아래로 떨어진 뒤 멈추기까지 걸린 시간 (100ms 이내 만점, 300ms 이상 0점) | 30% |
| 곧은 이동 (실험적) | 손목 이동 경로 중 수평·수직으로 움직인 길이의 비율. 호를 그리는 회전을 깎을 수 있어 비중을 작게 | 15% |
| 박자 | 멈춘 시각과 가장 가까운 카운트의 차이. 가이드 챌린지와 **같은 판정(Perfect/Good/Miss)·점수·콤보 함수**를 씀 | 별도 판정 |

- 히트 조건: 손목 속도가 1.2(어깨 너비/초) 이상으로 움직이다가, 0.4 이하로 80ms 이상 멈추고, 손목이 0.3 이상 이동. 속도는 2프레임 간격으로 재서 떨림을 줄이고, 멈춘 시각은 지연을 보정합니다.
  20~60fps에서 박자 오차가 실제와 일치하고, 15fps에서는 한 프레임(약 33ms) 이내입니다 (가상 입력 테스트).
- 팔을 내리고 있는 쪽(손목이 가슴 아래)은 "쓰는 팔"에서 제외합니다. 내린 팔은 수직이라 직각성을 공짜로 받기 때문입니다. 쓰는 팔이 없으면 히트로 치지 않습니다.
- 안무 구간(32카운트) 밖의 멈춤과, 멈추지 않는 4초 넘는 움직임은 점수를 주지 않습니다. 박자와 반 박자 사이의 히트는 아직 인정하지 않습니다.
- **인식 속도가 12fps 미만이면 화면에 경고**를 띄웁니다 (멈춤 감지가 부정확해짐).

### 가림에 대한 부분 대책

AI 생성 영상으로 확인한 결과, 손이 얼굴을 가리거나 팔이 교차해도 MediaPipe의 관절 신뢰도(visibility)는 거의 1.0이었습니다.
그래서 **팔 길이(윗팔·아랫팔)가 최근 중앙값의 0.6~1.6배를 벗어난 프레임은 사용하지 않습니다** (`BoneGate`).
해당 구간에서는 진행 중인 움직임 기록도 끊습니다. 완벽한 가림 감지가 아니며, 팔 길이가 비슷하게 추측되면 걸러내지 못합니다.
대신 가려진 구간에서 일어난 진짜 히트도 놓칩니다.

### 점검 결과 (실제 사람 검증이 아님)

- 가상 손목 움직임으로 시나리오 테스트(박자에 맞춘 멈춤, 어긋남, 서서히 멈춤, 쉬는 팔, 추적 끊김 등).
- 받은 AI 생성 영상(10초, 24fps)을 돌려 보면 속도 곡선에서 움직임·멈춤이 구분되고 5번의 히트가 감지됨.
  팔이 얼굴 앞을 지나는 구간(약 5.2~5.5초)은 팔 길이 검사가 걸러서 히트로 잡히지 않음.
  이 영상은 박자가 맞춰진 영상이 아니라 박자 판정은 점검하지 못했고, 실제 사람 동작과 같은지는 **확인 필요**입니다.

## 레슨과 포즈 — ⚠️ 모두 "임시 테스트 포즈"

검증된 텃팅 시범 자료를 확인하지 못해(작업 환경에서 외부 자료 사이트 접속 불가), 아래 포즈는
**MVP 테스트용으로 직접 정의한 것이며 전문 텃팅의 표준 동작이 아닙니다.** 화면에도 "임시 테스트 포즈"로 표시됩니다.
실제 기준 동작을 확보하면 `src/data/poses.ts`의 숫자만 바꾸면 됩니다.

| 레슨 | 방식 | 포즈 (임시) |
|---|---|---|
| 01 King Tut Basics (킹텃 기초) | 자세 유지 | 오른팔 ㄱ자 |
| 02 Box Tutting (박스 텃팅) | 자세 유지 | 양팔 프레임 (양팔 ㄱ자, 대칭) |
| 03 Tutting Flow (텃팅 플로우) | 순서대로 도달 | 오른팔 ㄱ자 → 왼팔 ㄱ자 → 양팔 프레임 |

Lesson 03은 지금은 박자 없이 "순서대로 도달 + 단계별 걸린 시간"만 봅니다. 박자(비트) 타이밍 평가는 리듬 챌린지 단계에서 추가합니다.

## 판정 기준 (`src/data/poses.ts`)

방향은 **거울 화면 기준 절대 각도**: 0° = 화면 오른쪽, 90° = 위, 180° = 화면 왼쪽.
(사용자의 오른팔이 바깥으로 뻗으면 0°, 왼팔이 바깥으로 뻗으면 180°)
용어: **윗팔** = 어깨→팔꿈치, **아랫팔** = 팔꿈치→손목.

| 항목 | 허용 범위 | 비고 |
|---|---|---|
| 팔꿈치 각도 (목표 90°) | ±15° | 확정값 |
| 윗팔 방향 | ±20° | 초기 가정값, 조정 필요 |
| 아랫팔 방향 | ±20° | 초기 가정값, 조정 필요 |
| 좌우 균형 (양팔 포즈만) | 팔꿈치 각도 차 15°, 손목 높이 차 25% | 초기 가정값 |

- 팔 하나의 점수: 팔꿈치 40% + 윗팔 방향 30% + 아랫팔 방향 30%. 양팔 포즈는 두 팔 평균 90% + 좌우 균형 10%.
- **Perfect**: 모든 항목이 허용 범위 이내 (이 상태로 0.7초 유지하면 성공)
- **Good**: 일치도 70 이상이고, 어떤 항목도 허용 범위의 2배를 넘지 않음
- **Adjust**: 그 외
- 평가하지 않는 팔은 자유. 추적이 끊기면 0.5초 유예 후 판정 보류.
- "손목 상대 위치"는 윗팔·아랫팔 방향과 같은 정보라 별도 점수로 이중 계산하지 않았습니다.
  (양팔 포즈에서는 좌우 손목 높이 차이로 반영)

## MediaPipe로 판정 가능 / 불가능

| 가능 (Pose Landmarker, 정면 2D) | 불가능·제외 |
|---|---|
| 어깨·팔꿈치·손목 위치, 팔꿈치 각도, 팔 방향 | 손가락 개별 동작, 손바닥 방향 (Hand Landmarker 필요) |
| 좌우 대칭·높이 차이 | 카메라 앞뒤로 움직이는 동작 (2D로는 각도 왜곡) |
| 자세 유지 시간, 순서·도달 시간 | 동작의 예술적 완성도, 전문가 수준 평가 |

## 좌우 처리 원칙

판정은 MediaPipe의 **몸 기준** 인덱스(오른쪽 어깨 12, 팔꿈치 14, 손목 16)를 사용하고, 화면 표시만 거울 처리합니다.
카메라 원본 좌표 → `toUserView()`(x 반전 + 가로세로 비율 보정) → 각도 계산.
